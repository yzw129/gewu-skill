# GEWU · 格物（Research Edition）

## 定位

把研究方向内的**真实文献证据**转换成**有条件、有边界、可检查的科研方法规则**，再组合成方向专属 Skill。禁止只复述论文摘要或套用某一目标期刊模板。

## 启动判断

- 首选 `distill`：用户给研究方向或一组论文，按 P0–P5 形成规则与方向 Skill。
- `apply`：用户已有经过核查的方向知识库，用于科研选题、研究设计或论文审查。
- 期刊匹配仅属于 `apply` 后期阶段；不能将期刊作为默认的蒸馏目标。
- 当前不执行人物、组织、风格、项目等非科研蒸馏。

## 必做步骤

严格按 `references/workflow.md` 执行；必要时载入 `references/extraction.md`、`references/distillation.md` 和 `references/validation.md`。

1. **界定**：建立 `project.json`，给出研究对象、边界、检索式、纳排与评价规则；冻结协议。
2. **采集**：检索多个来源并保留可复现日志；若没有联网/全文能力，明确未完成，不伪造文献。
3. **提取**：逐篇登记 `papers.json`，只对可读内容做相应层级的主张；完整论文才能提取具体实验细节。
4. **蒸馏**：分组比较并登记 `rules.json`；逐条包含条件、建议、解释、可定位证据、反例及局限；区分文献事实与研究假设。
5. **生成**：仅在证据审查后生成方向 Skill，未审查规则只能以草稿预览。
6. **验证**：冻结留出论文和指标，比较基线并输出核查结果；脚本结构通过不能冒充科研有效性。

## 数据与操作

- 目录格式见 `templates/project.json`、`templates/paper-record.json`、`templates/rule-record.json`。
- CLI 位置：`scripts/gewu.py`，支持 `init`、`check`、`freeze`、`compile`、`report`，详见仓库 README。
- `freeze` 仅对配置做规范化锁定；需结合版本控制审查后续人工修改。
- 不允许综合集规则引用留出论文、虚构 DOI/结果、以引用量代替证据、根据失败结果静默变更协议。

## 输出规范

默认提供：检索协议、文献证据表、科学问题/方法矩阵、候选规则和局限、生成的方向 Skill、验证记录。对每一项标记：真实核查/模型推断/待验证/未执行。没有足够证据时只提供已完成的部分和缺口。
