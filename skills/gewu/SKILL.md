# Gewu · 格物 — 能力蒸馏与可验证进化

## 目标

Gewu 不只“记住研究领域信息”，而要将可信来源与成功/失败案例转化为**可执行、可检查、可迁移**的方法。当前能力域：科研推理、学术写作、科学绘图、学术汇报。核心引擎保持与领域解耦；领域模块各自维护专门规范和评价方式。

**参数更新不是本项目当前能力。** 学习意味着生成并使用可审查的外部 Skill；成长必须通过未见任务上的同条件对照实验确认。

## 统一流程

1. **界定任务**：明确学什么、给谁用、需要产出什么、什么情况视为成功/失败。
2. **收集来源**：论文、现成 Skill、官方规范、真实脚本、作品示例与失败案例。记录出处、具体位置、许可范围及实际核查层级。
3. **蒸馏规则**：将知识/案例转换为 IF（触发条件）→ THEN（行动）→ BECAUSE（依据）→ EXCEPT（失效条件）→ CHECK（如何验证）。区分领域事实与方法规则。
4. **编译技能**：按任务选择领域模块；候选规则只能生成明确标记的 preview，正式编译要求来源和规则审查、评估计划冻结。
5. **执行与检查**：使用合适的工具产出实际文件/结果，并核查**原始数据、运行日志、内容准确性与输出格式**；不能以语言描述代替实际执行。
6. **评估与迭代**：固定对照条件；分开知识增益与方法增益；开发集可用于改进，独立测试集仅用于最终确认；失败记录可追踪。

## 领域路由

根据所需产物读取相应文件，不能仅凭关键词做混合：
- 科研问题、方法与实验设计 → `domains/research/SKILL.md`
- 论文写作、摘要、引言、结果、讨论、文字修改 → `domains/writing/SKILL.md`
- 数据图表、模型机制图、研究流程图 → `domains/visualization/SKILL.md`
- 科研汇报 PPT、报告结构与设计 → `domains/presentation/SKILL.md`

多领域任务：各领域独立生成/审查成果，再按内容依赖整合。例如实验数据核查 → 统计作图 → 结果写作 → 汇报；各环节的质量指标不能相互替代。

## 已有命令的兼容关系

- 科研文献解析：`scripts/gewu_v03.py`。
- 科研推理/版本演化：`scripts/gewu_v04.py`。
- 三组知识/方法对照：`scripts/gewu_eval_v041.py`。
- 通用能力卡、审查、冻结与编译：`scripts/gewu_capabilities.py`（v0.5）。
- 领域机制与目标见 `references/capability-model.md`。

v0.5 的脚本是**能力定义、门禁和编译框架**，并未实现自动学习所有外部 Skill、自动写论文、自动绘图或自动盲审。写作与绘图的实际执行仍需调用适用的文档和绘图工具，并保留可复现证据。

## 必须坚持

- 来源已读取、原文核查、输出实际执行和科研有效性验证是不同状态。
- 不虚构文献、公式、图件、数据、实验测试结果或能力提升分数。
- 不能仅模仿外部 Skill 的长段文本；尊重许可，提取可验证的通用方法。
- 写作不能引入无出处的事实；绘图不能修改数据含义；机制图不能绘制虚假的物理/逻辑关系。
- 没有独立评价时，只能说“已编译/未验证”，不能说“已学会”。

## 经验反馈机制（优先级 1）

如用户要比较历史经验是否改善科研能力，先读取 `references/experience-feedback.md`。只允许通过外部审查、可追溯到不在测试集内的来源任务的经验参与记忆组；禁止用待评估任务的答案事后蒸馏经验。冻结10项任务、两组共同基础 Skill、模型、评价标准、成本费率，再逐任务执行、外部审查与修订。所有20组任务完成前不得宣布成功率提高。实现：`scripts/gewu_experience.py`。

## 从私人历史任务中蒸馏候选经验

用 `scripts/gewu_history_distill.py` 将已提炼的私人候选规则转换为未验证的 EXP1 经验库。严禁自动升级至 `verified`；被学习的任务必须从本轮独立测试中排除。原始证据与用户成果文件不上传公共仓库。
