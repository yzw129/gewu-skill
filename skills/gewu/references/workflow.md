# Research-first 蒸馏工作流

只研究科研方向；先确定科学问题与证据，再选择期刊。不可因期刊偏好而逆向编造研究问题。

P0 / DEFINE：输出 `project.json`，检索数据库、查询式、纳排标准和拟开展的验证指标。冻结检索协议。

P1 / DISCOVER：跨期刊采集论文，保留检索式、日期、数量、排除理由和重复项；优先出版社、DOI、官方索引及用户提供的全文。记录题名/版本与实际阅读层级。严禁虚构已读全文。

P2 / EXTRACT：逐篇解析科学问题、研究假设、数据、模型、对照、指标、结果、机制解释、局限，并逐条绑定章节/图表/页码。详见 `extraction.md`。

P3 / DISTILL：预先固定留出论文集合；仅用综合集合提炼规则。逐条讨论条件、动作、证据、相反证据、失效边界。详见 `distillation.md`。

P4 / COMPILE：先执行结构检查，然后把人工核对过的规则编译为方向专属 Skill。candidate 只能生成预览，不得冒充已审查技能。

P5 / VALIDATE：在预留论文与研究情境上比较裸模型、直接检索、蒸馏 Skill；事先固定评估规则，记录错误。详见 `validation.md`。

P6 / APPLY：基于生成的 Skill 设计研究假设、实验与审稿清单；期刊只在研究贡献清晰后推荐。不得虚称开展过实验、检索或统计验证。

## 数据可追溯

- 文献元数据只证明论文身份，不证明模型细节。
- 摘要仅用于摘要级命题；Methods/Results 必须有全文支持。
- 文献结论、推断、研究假设、建议在数据中显式区分。
- 负面证据不抹平；须保留条件差异与冲突。
- 对新论文或新证据做版本追加，说明哪些旧规则需要复核。
